# Data Preparation and Split Notes

This document records how the datasets were downloaded, organized, generated, and split for the ClaimCheck project. It is intended to help team members understand and reuse the data and reproduce the Inserted Error Set.

## 1. RAGBench

**Source:** https://huggingface.co/datasets/galileo-ai/ragbench

**Subsets:** FinQA and TAT-QA

### Data Preparation

The datasets are downloaded from Hugging Face using the `datasets` Python library.

We use the official training, validation, and test splits without additional random splitting.

The following 12 columns are retained:

`id`, `question`, `documents`, `response`, `documents_sentences`, `response_sentences`, `sentence_support_information`, `unsupported_response_sentence_keys`, `overall_supported_explanation`, `relevance_explanation`, `dataset`, `split`.

The `dataset` and `split` columns identify the source subset and the original split.

No changes are made to the original questions, responses, documents, or annotations. Nested fields may be serialized when exporting to CSV.

### Notes for Model Development

The following fields contain reference annotations or explanations and should not be used as model inputs:

- `sentence_support_information`
- `unsupported_response_sentence_keys`
- `overall_supported_explanation`
- `relevance_explanation`

Claim decomposition, label conversion, and other model preprocessing steps are not performed during data splitting.

## 2. Inserted Error Set

**Final size:** 400 examples

**Source:** SEC annual 10-K filings, XBRL company facts, and inline XBRL segment information.

The Inserted Error Set contains automatically generated financial claims from 40 distinct companies. It includes 300 General Claims and 100 Storyboard B claims.

### Data Preparation

Company candidates are screened against FinanceBench company information and the processed RAGBench FinQA and TAT-QA datasets to reduce potential overlap.

Financial values are extracted from SEC filings and XBRL data. The generation process uses fixed rules to create correct claims and claims with inserted errors.

The dataset is generated automatically without manually entering financial values or claim labels.

A fixed random seed of 42 is used. The selected companies and their split assignments are saved in `locked_company_split_40.csv`.

### General Claims

The General Claims dataset contains 300 examples from 30 companies, with 10 claims per company.

Each company contributes:

| Claim Type | Examples per Company | Label |
|---|---:|---|
| Supported | 2 | Supported |
| Numerical | 3 | Unsupported |
| Temporal | 2 | Unsupported |
| Metric Confusion | 2 | Unsupported |
| Unit | 1 | Unsupported |
| **Total** | **10** | |

The errors are generated by modifying financial values, reporting periods, metric names, or units while retaining the corresponding reference values and source information.

### Storyboard B Claims

The Storyboard B dataset contains 100 examples from 10 additional companies, with 10 claims per company.

Each company contributes:

- 8 Unsupported claims that incorrectly present segment revenue as the company's total revenue.
- 2 Supported claims that correctly identify segment revenue.

Segment revenue values are extracted automatically from SEC inline XBRL filings. The extraction checks reporting periods, segment contexts, USD units, and consolidated revenue comparisons.

The final Storyboard B dataset contains 80 Unsupported claims and 20 Supported claims.

### Split Design

The dataset is split by company. Each company appears in only one split and belongs to either General Claims or Storyboard B, not both.

| Dataset | Training | Validation | Testing | Total |
|---|---:|---:|---:|---:|
| General Claims | 210 | 60 | 30 | 300 |
| Storyboard B | 30 | 20 | 50 | 100 |
| **Total** | **240** | **80** | **80** | **400** |

The overall split proportions are 60% training, 20% validation, and 20% testing.

The 40 companies are distributed as follows:

| Dataset | Training | Validation | Testing | Total |
|---|---:|---:|---:|---:|
| General Claims | 21 | 6 | 3 | 30 |
| Storyboard B | 3 | 2 | 5 | 10 |
| **Total** | **24** | **8** | **8** | **40** |

The testing split intentionally contains more Storyboard B examples to evaluate segment revenue errors.

### Reproducibility and Validation

The generation process saves the selected companies, source snapshots, output CSV files, and SHA256 checksums.

The main reproducibility files include:

- `locked_company_split_40.csv`: Fixed company selections and split assignments.
- `source_snapshots/`: Saved SEC source data and filings.
- `reproducibility_manifest_400.json`: Source input, snapshot, and output checksums.
- `output_sha256_400.csv`: Output file checksums.
- `general_claims_300.csv` and `storyboard_b_100.csv`: Complete generated datasets.
- Separate training, validation, and testing CSV files for both datasets.

A separate reproduction notebook allows team members to recreate the 400 claims using the saved source files without downloading SEC data again.

The reproduction process verifies the source input and snapshot hashes against the saved manifest before regenerating the claims.

The reproduction notebook has been executed successfully. All eight regenerated claim CSV files matched the original SHA256 hashes, and the original output files were not modified.

The generation code also checks the number of claims, label distributions, company uniqueness, and split assignments.

These checks establish reproducibility and structural consistency. They do not replace manual review of financial statements and segment definitions.

### Notes for Model Development

The training split is intended for developing baseline rules and classical model scope features. DeBERTa and the LLM Judge will not be trained on this dataset.

Reference values, error types, and source annotations are retained for verification and evaluation. Fields containing ground truth information must not be included as model inputs.

## 3. FinanceBench

**Source:** https://huggingface.co/datasets/PatronusAI/financebench

### Split Design

| Split | Examples |
|---|---:|
| Testing | 147 |
| Blind Test | 3 |
| **Total** | **150** |

FinanceBench is reserved for testing only and is not used for training or threshold tuning.

The three blind test examples will be kept separate for the final showcase and excluded from model development.

## 4. General Notes

- All models should use the same predefined splits for each dataset.
- Company assignments in the Inserted Error Set are fixed to prevent company overlap across splits.
- Original annotations and source information should be preserved for evaluation.
- Reference labels, reference values, and explanations must not be included in model inputs.
- The Inserted Error Set should be reproduced using the saved snapshots and reproduction notebook rather than downloading updated SEC data.
- Any changes to source data, generation rules, or split assignments should be documented and treated as a new dataset version.
- Automatic validation and successful reproduction do not guarantee that every financial claim has been manually verified.
